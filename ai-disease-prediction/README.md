# AI Disease Prediction System

A Flask web application in which a user selects symptoms (and optionally age and gender) and a scikit-learn model estimates which disease from a predefined list the symptoms most resemble.

> ## ⚠️ Medical safety disclaimer
> **This is an educational/demo project. It is not a medical device and its output is not a medical diagnosis.**
> Predictions are statistical estimates produced by a machine-learning model trained on limited data. They can be wrong, they cannot account for your medical history, and they must never be used to decide whether to seek, delay or avoid medical care.
> **Always consult a qualified healthcare professional.** If you think you may be seriously unwell, contact a doctor or your local emergency number immediately.
> The application never recommends medicines or treatments.

> ## ⚠️ The bundled dataset is synthetic
> `data/disease_symptoms.csv` is **generated by a script** from hand-written symptom probabilities (`src/generate_sample_data.py`). It exists only so the pipeline can run end to end. **Scores measured on it say nothing about real-world accuracy.** For meaningful evaluation, replace it with a real public dataset (see [Dataset](#dataset)). The app labels synthetic-data models with a banner on every page.

## Features

**Core**
- Home page with project explanation, *Start Prediction* button and a prominent medical disclaimer.
- Prediction page: searchable symptom selector, checkbox chips, optional age/gender (shown only if the trained model uses them), loading animation, friendly validation errors.
- Result page: predicted disease, probability clearly labelled as a *model estimate*, ranked alternatives, selected symptoms, general educational information, and a strong recommendation to consult a professional. No personalised medication or treatment advice.
- Model dashboard: dataset size, number of diseases and symptoms, accuracy, precision, recall, F1, model comparison, class distribution, confusion matrix, feature importance, per-disease scores and model versions.
- JSON API: `POST /predict` plus helper endpoints, with OpenAPI description.
- Unit and API tests (44 tests).

**Advanced (all implemented)**
| Feature | How |
|---|---|
| Explainable AI | Per-prediction *occlusion* explanation (how the estimate changes if each symptom is removed) on the result page; model-level *permutation importance* (and native importance where available) on the dashboard. SHAP is not required - see [Future improvements](#future-improvements). |
| Prediction history | Stored in SQLite per browser (anonymous cookie) or per account; can be deleted. |
| User authentication | Register / sign in / sign out (hashed passwords, CSRF tokens, session reset on login). Anonymous history is adopted on sign-in. |
| Downloadable report | Standalone HTML report per prediction (`/result/<id>/report`) plus a print-friendly stylesheet. |
| Interactive charts | Chart.js bar charts and an interactive confusion-matrix heat map. |
| Docker support | `Dockerfile` + `docker-compose.yml` (model is trained inside the image). |
| REST API documentation | `/api/docs` page and `/api/openapi.json` (OpenAPI 3). |
| Model versioning | Every training run saves a versioned model + metrics and appends to `models/registry.json`. |

## Dataset

The pipeline expects `data/disease_symptoms.csv`. Two layouts are detected automatically (details in [`data/README.md`](data/README.md)):

- **Wide**: one 0/1 column per symptom + a `disease` column (+ optional `age`, `gender`).
- **Long**: `Disease, Symptom_1, Symptom_2, …` holding symptom *names*, as in the Kaggle *Disease Symptom Prediction* file. A target called `prognosis` (Kaggle *Disease Prediction Using Machine Learning*) also works.

**Using a real dataset**

1. Download a public symptom dataset (for example from Kaggle or the UCI repository) and **check its licence and provenance**.
2. Save it as `data/disease_symptoms.csv` and delete `data/disease_symptoms.meta.json`.
3. Run `python -m src.train`. The dashboard will then stop showing the "synthetic" banner.
4. Add entries for your diseases to `data/disease_info.json` (have a clinician review the text); others get a generic message.

**The bundled sample** has 4,000 rows, 10 diseases and 34 symptoms plus age and gender, with deliberately unequal class sizes (7:1) and a few blanks so cleaning and imputation are exercised. Regenerate with `python -m src.generate_sample_data --rows 6000 --seed 7`.

**Dataset limitations you should keep in mind**
- Symptom datasets are usually small, simplified and often partly artificial. Several popular public ones are reported to be so templated that models reach near-perfect accuracy - treat such scores with suspicion.
- Symptoms are binary: no severity, duration, onset, medical history, medications or test results.
- Closed world: the model can only name diseases it was trained on and will always pick one, even when none fits.
- **Class imbalance**: common diseases dominate. Models can look accurate by favouring them. This project uses class weights and reports macro-averaged metrics and per-disease results.
- Label noise, selection bias and demographic skew in the source data carry straight into predictions.

## Machine-learning methodology

1. **Load** the CSV and normalise column names (`Skin Rash` → `skin_rash`). Long layouts are converted to wide.
2. **Clean** (`src/preprocessing.py`): drop empty rows and rows without a target; coerce symptoms to 0/1; validate age (0–120) and standardise gender; drop symptom columns that are never present; **remove exact duplicate rows before splitting**; drop diseases with fewer than 10 rows (cannot be split or evaluated). Every step is recorded in a report shown on the dashboard.
3. **Missing values**: symptom blank → "not reported" (0); age blank → training-set median; gender blank → most frequent training category; target blank → row dropped.
4. **Encode**: symptoms stay binary; age is standardised; gender is one-hot encoded (unknown categories ignored at prediction time).
5. **Split**: stratified train / validation / test = 64 / 16 / 20 % with a fixed seed (`RANDOM_STATE = 42`), so runs are reproducible.
6. **Avoid data leakage**
   - Imputers, scaler and encoder live in a scikit-learn `Pipeline` with the classifier, so they are **fitted on training rows only**.
   - Duplicates are removed before splitting.
   - Models are compared on the **validation** set; the **test set is used once**, after selection.
   - Optional k-fold cross-validation uses train + validation only.
7. **Train and compare** three models - Logistic Regression, Random Forest, SVM (RBF) - all with class weighting. The winner is the one with the best **validation macro-F1** (accuracy breaks ties); no algorithm is assumed best.
8. **Refit** the selected pipeline on train + validation, evaluate once on the test set, compute permutation importance, and save the model (`joblib`), metrics (JSON) and figures (PNG).

## Model evaluation

Computed and written to `models/metrics.json` on every run (nothing is hard-coded):
accuracy, balanced accuracy, macro- and weighted-averaged precision/recall/F1, per-disease precision/recall/F1/support, confusion matrix, model comparison on the validation set, optional cross-validated macro-F1, and feature importance.

Example console output from one run on the **synthetic** sample (your numbers will differ slightly with library versions):

```
Selected: SVM (RBF)  |  test accuracy 0.963  |  macro precision 0.962  recall 0.966  F1 0.964
NOTE: trained on SYNTHETIC demo data - these numbers are not meaningful for real-world use.
```

How to read them responsibly:
- **A high test score does not mean the system is medically reliable.** It means the model fits *that dataset*. Real patients, rare diseases and unreported symptoms are not represented.
- Macro metrics weight every disease equally, so rare diseases count as much as common ones. Check per-disease scores - small classes have very few test rows and noisy scores.
- One hold-out split has sampling noise; small differences between models are not meaningful.
- The "confidence" shown to users is the model's own probability estimate. SVM probabilities come from internal Platt scaling, and no model here is guaranteed to be calibrated.

## Installation

Requires **Python 3.11+**.

```bash
cd ai-disease-prediction
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

> A trained model (`models/disease_model.joblib`) is included. It was saved with a specific scikit-learn version; if you see a version warning or load error, simply retrain (next section).

## Training the model

```bash
python -m src.train                       # uses data/disease_symptoms.csv
python -m src.train --seed 7 --cv-folds 5 # options
python -m src.train --data path/to/your.csv --model-dir models
python -m src.train --no-plots            # skip PNG figures
```

If `data/disease_symptoms.csv` is missing, a clearly-marked synthetic file is generated first (disable with `--no-sample-fallback`).
Outputs: `models/disease_model.joblib`, `models/metrics.json`, `models/registry.json`, `models/versions/*`, `static/img/*.png`.
Training takes under a minute on the sample data (permutation importance is the slowest step).

A narrated version of the same steps is in `notebooks/model_training.ipynb` (`pip install jupyter` to open it).

## API documentation

Interactive overview at **`/api/docs`**, machine-readable spec at **`/api/openapi.json`**.

### `POST /predict`

`Content-Type: application/json`

```json
{
  "symptoms": ["fever", "cough", "fatigue"],
  "age": 34,
  "gender": "female",
  "save": false
}
```

- `symptoms` (required): non-empty list of identifiers from `GET /api/symptoms` (case-insensitive, duplicates ignored, max 40).
- `age` (optional): 0–120. `gender` (optional): `female`, `male` or `other`. Both are ignored if the model was trained without them.
- `save` (optional, default `true`): store the result in the caller's cookie-based history. Use `false` for stateless API calls.

Response `200`:

```json
{
  "prediction": "Example Disease",
  "confidence": 0.82,
  "top_predictions": [{"disease": "Example Disease", "probability": 0.82}],
  "selected_symptoms": ["fever", "cough", "fatigue"],
  "explanation": [{"symptom": "fever", "label": "Fever", "effect": 0.31}],
  "low_confidence": false,
  "model_version": "20261003-065400",
  "trained_on_synthetic_data": true,
  "disclaimer": "This is an educational demo...",
  "id": 12,
  "result_url": "/result/12"
}
```

`confidence` is a model probability estimate, **not** the chance that the person has the disease. `id`/`result_url` appear only when saved.

Errors are `{"error": "..."}` with status `400` (empty, malformed or unknown input), `413` (body over 64 KB) or `503` (model not trained).

```bash
curl -s -X POST http://127.0.0.1:5000/predict \
  -H "Content-Type: application/json" \
  -d '{"symptoms": ["wheezing", "chest_tightness"], "save": false}'
```


## Model versioning

Each `python -m src.train` run writes:
- `models/versions/disease_model_<UTC timestamp>.joblib` and `metrics_<timestamp>.json`
- a copy of the new model as `models/disease_model.joblib` (what the app loads) and `models/metrics.json`
- a new row in `models/registry.json` (version, model, time, test accuracy/F1, whether the data was synthetic)

The dashboard lists all versions. **To roll back**, copy the older `versions/disease_model_<ts>.joblib` over `models/disease_model.joblib` and `versions/metrics_<ts>.json` over `models/metrics.json`, then restart the app (the model is loaded once per process).

## Limitations

- **Not clinically validated.** No clinical study, regulatory review or expert oversight. It must not be used for real health decisions.
- The shipped data is synthetic; real-world accuracy is unknown. Public symptom datasets are small and often artificial.
- Only a short, fixed list of diseases; it always returns one of them, even for symptoms outside that list. Low-confidence results are flagged, but a high-confidence result can still be wrong.
- Binary symptoms only - no severity, duration, history, vitals, tests or medications. Many illnesses share symptoms, so ranked alternatives matter more than the top label.
- Class imbalance and dataset bias (age, gender, region) may make some groups and diseases less accurate than the averages suggest.
- Explanations (occlusion, permutation importance) describe the *model's behaviour*, not medical causation.
- Educational text in `data/disease_info.json` is brief and general; it has not been clinically reviewed for your jurisdiction.
- Privacy: history is stored unencrypted in SQLite and passwords are hashed but this app has no rate limiting, email verification or password reset. Do **not** deploy publicly or enter real personal health information without adding proper security, privacy and legal safeguards.
- `joblib` files execute code when loaded: only load model files you trained yourself.
